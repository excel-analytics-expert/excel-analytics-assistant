# 清掃シフト管理・出退勤ダッシュボード

清掃業向けのシフト管理・ダッシュボード・QRコード出退勤アプリです。

## 主な機能

- **ダッシュボード** (`/dashboard`): 本日の現場ごとの人員充足状況・出退勤状況、週間シフト状況を一覧表示
- **シフト管理** (`/shifts`): シフトの作成・編集（担当者/時間変更）・削除
- **自動シフト作成** (`/shifts/generate`): 期間と現場を指定すると、必要人数・スタッフの割当回数・現場ごとのリーダー配置を考慮して自動でシフトとスタッフ割当を生成
- **現場QRコード** (`/sites`, `/sites/[siteId]/qr`): 現場ごとの出退勤用QRコード。1分ごとに自動で切り替わり、各コードは発行から5分で失効する（写真に撮って後から使う遅刻・早退の偽装を防止）
- **出退勤打刻** (`/attend/[token]`): QRコードを読み取ると開く打刻ページ。本人を選択し、その場で撮影した写真を添えて出勤・退勤を記録。スマートフォンを持たないスタッフは、リーダーの端末でこの画面を開いて順番に操作することで同じ方法で打刻できる（共有端末利用）
- **現場の地図案内**: 現場に住所（任意でGoogleマップのURL）を登録すると、スタッフのスマホ（打刻画面・自分の予定）に「経路を案内」「地図で見る」ボタンが出る。Googleマップが開く
- **自分の予定** (`/my`): スタッフが自分の名前を選ぶと、今後7日間の現場・時間・地図と出勤状況が見られる
- **遅刻・遅延の届出**: 開始時刻を過ぎて出勤すると届出フォームが自動で開く。遅刻の理由（自由記入）と遅延証明書の写真（背面カメラ）を提出でき、ダッシュボードには「遅刻○分」と届出が表示される
- **トラブル・申し送り報告**: 打刻画面からいつでも、自由記入と任意の写真でトラブルや申し送り事項を報告可能。リーダー・本社はダッシュボードで確認できる
- **スタッフ管理** (`/staff`): スタッフの追加、リーダー/メンバーの設定、稼働状態の切り替え

## セットアップ

```bash
npm install
cp .env.example .env   # 本番では APP_BASE_URL を公開URLに設定
npx prisma migrate dev
npm run db:seed        # サンプルデータ投入（任意）
npm run dev
```

`APP_BASE_URL` は、QRコードに埋め込むURLのベースになります。本番環境では実際の公開URL（例: `https://shift.example.com`）に設定してください。未設定の場合は、QR画面を開いたときのURLがそのまま使われます。

## スマホ（iPhone / Android）での利用

QRコードは iPhone の標準「カメラ」アプリ、Android の「カメラ」アプリ・「Googleレンズ」、LINEのQRリーダーで読み取れます（専用アプリは不要）。

**社内で試す（同じWi-Fi）**

1. PCで `npm run dev` を実行し、表示される `Network: http://192.168.x.x:3000` を確認
2. **PCのブラウザでも `localhost` ではなくそのIPアドレスで** QR画面（`/sites/…/qr`）を開く
   - `localhost` で開くとQRの中身も `localhost` になり、スマホからは開けません（画面に赤い警告が出ます）
3. スマホのカメラでQRを読み取る

社内LAN（192.168.x.x / 10.x.x.x / 172.x.x.x）以外のアドレスから開発サーバーを使う場合は、`DEV_ALLOWED_ORIGINS` にホスト名を追加してください（未設定だとスマホ側で画面のボタンが動きません）。

**本番運用**

- HTTPSで公開し、`APP_BASE_URL` にそのURLを設定してください。
- HTTPS環境では、QR表示中の端末の画面が自動で消えないようになります（iOS 16.4以降・Android Chrome）。HTTPでは効かないため、端末の自動ロックをオフにしてください。
- 写真はブラウザで開ける形式が必要です。Androidの一部機種（Galaxy等）でHEIC形式に設定されている場合は読み込めないため、画面の案内に従ってカメラの保存形式をJPEGにしてください（iPhoneは自動でJPEGに変換されます）。

## 技術スタック

- Next.js (App Router) + TypeScript
- Prisma + SQLite（開発用。本番で複数台運用する場合はPostgres等への切り替えを推奨）
- qrcode（QRコード画像生成）
- Tailwind CSS

## データモデル概要

- `Staff`: スタッフ（リーダー/メンバー）
- `Site`: 清掃現場（必要人数・標準勤務時間）
- `Shift`: 現場ごとの日次シフト
- `ShiftAssignment`: シフトへのスタッフ割当
- `Attendance`: 出退勤記録（シフト×スタッフ単位）。出勤時・退勤時に撮影した本人確認用写真のファイル名も保持
- `DailyQrToken`: 現場ごとに日替わりで発行されるQRコード用トークン（不正防止のため日付が変わると無効化）
- `IncidentReport`: トラブル・申し送り報告、遅刻・遅延の届出（`kind` で区別。テキスト＋任意の写真）
- `Site.mapUrl`: 現場のGoogleマップURL（任意。Google以外のURLは登録時に拒否）

## 出退勤の本人確認（写真撮影）について

スマートフォンを持たないスタッフのため、出退勤時に**カメラで撮影した写真を本人確認の記録として添付**できるようにしています。

- これは「写真を記録に残し、リーダー・本社が目視で確認する」仕組みであり、AIによる自動顔照合（生体認証）は行っていません。
- 写真は `public/` の外（`storage/attendance-photos/`）に保存し、`/api/attendance/photo/[filename]` 経由でのみ配信されます。ただし本アプリには**認証（ログイン）機能が現状ありません**。社内ネットワーク限定で運用する、リバースプロキシ等でBasic認証をかける、といった追加対応を本番運用前に行ってください。
- 将来的にAIによる自動顔照合（顔画像から生体認証データを生成して照合する方式）を導入する場合は、個人情報保護法上「要配慮個人情報」の取得にあたるため、本人への利用目的の明示・同意取得、データの保管期間・削除ルールの整備が必要です。導入する際はご相談ください。
- `storage/` ディレクトリは `.gitignore` 対象です。スタッフの写真データを誤ってリポジトリにコミットしないよう注意してください。

## 運用上の注意

- 日付・「本日」の判定はすべて日本時間（Asia/Tokyo）基準で統一しています。
- QRコードは1分ごとに新しいものに切り替わり、各コードは発行から5分で使えなくなります（`src/lib/qr-token.ts` の `QR_ROTATION_SECONDS` / `QR_TOKEN_TTL_SECONDS` で調整可能）。印刷した紙はすぐ無効になるため、リーダーの端末やタブレットにQR画面を表示したままにしてください。スマホを持たない人は、同じ画面の「この端末で打刻する」から打刻できます。
- QR表示画面（`/sites/[siteId]/qr`）のURLを知っていれば誰でも最新のQRを取得できてしまうため、この画面はリーダー・本社のみが開くようにしてください（ログイン機能は未実装）。
- 自動シフト作成は「必要人数を満たすように、割当回数の少ないスタッフから優先的に、同日重複なく」割り当てる簡易アルゴリズムです。有給・シフト希望などの細かい制約には対応していないため、作成後は `/shifts` で内容を確認・調整してください。
- ダッシュボードの「トラブル・申し送り」欄には直近7日分の報告が表示されます。写真付きの報告は「写真を見る」リンクから確認できます。
